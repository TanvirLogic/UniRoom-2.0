## ১. ভূমিকা: আমরা কেন সম্পূর্ণ প্রজেক্ট নতুন করে বানাচ্ছি?

### সাধারণ স্টুডেন্ট প্রজেক্ট বনাম এন্টারপ্রাইজ প্রজেক্টের পার্থক্য:
- **সাধারণ স্টুডেন্ট প্রজেক্ট:** কোনো আর্কিটেকচার থাকে না, UI-এর ভেতরেই ডাটাবেজের কোড লেখা হয় (যেমন: বাটন ক্লিকে সরাসরি ডাটাবেজ আপডেট), টেস্ট থাকে না, কোনো সার্ভার-সাইড সিকিউরিটি থাকে না।
- **এন্টারপ্রাইজ সফটওয়্যার ইঞ্জিনিয়ারিং প্রজেক্ট:**
  1. কোড হবে **Clean, Modular & Decoupled** (একটি অংশ পরিবর্তন করলে অন্য অংশ ভাঙবে না)।
  2. **Clean Architecture & Domain-Driven Design (DDD)** অনুসরণ করবে।
  3. নিজস্ব **Secure Backend & Database** থাকবে (শুধু ক্লায়েন্টের ওপর নির্ভর করবে না)।
  4. **Automated Testing & CI/CD Pipeline** থাকবে।
  5. **Real-time, Concurrency & Conflict-handling** সমাধান করবে।

## ৩. প্রতিটি টেকনোলজি বাছাইয়ের পেছনের গভীর কারণ (The "Why")

### ৩.১ Frontend: Flutter + Riverpod 2.x + Clean Architecture

#### কেন Flutter?
- **সিঙ্গেল কোডবেস, মাল্টি-প্ল্যাটফর্ম:** একই ডার্ট (Dart) কোড দিয়ে Android, iOS এবং Web তৈরি করা যায়। 
- **নেটিভ পারফরম্যান্স:** ফ্ল্যাটার সরাসরি নেটিভ ARM বাইনারিতে কম্পাইল হয়, ফলে UI অত্যন্ত স্মুথ (60fps/120fps) থাকে।

#### কেন Provider বাদ দিয়ে Riverpod 2.x?
1. **No `BuildContext` Dependency:** Provider-এ ডাটা রিড করতে সবসময় `BuildContext` লাগত, যা বিজনেস লজিক লেয়ারে পাওয়া কঠিন। Riverpod-এ যেকোনো জায়গা থেকে নিরাপদে প্রোভাইডার এক্সেস করা যায়।
2. **Compile-time Safety:** Provider রানটাইমে ক্র্যাশ করতে পারত যদি প্রোভাইডার ট্রি-তে পাওয়া না যেত (`ProviderNotFoundException`)। Riverpod কম্পাইল টাইমে গ্যারান্টি দেয় যে ডাটা আছে।
3. **`AsyncValue` এর জাদু:** ইন্টারনেটের ডাটা হ্যান্ডেল করার ৩টি স্টেট থাকে: `Loading`, `Data`, এবং `Error`। Riverpod-এর `AsyncValue` এই ৩টি স্টেটকে চমৎকারভাবে হ্যান্ডেল করতে বাধ্য করে, ফলে অ্যাপ কখনও আনহ্যান্ডেলড এররে ক্র্যাশ করে না।
4. **Auto-dispose & Caching:** স্ক্রিন বন্ধ হয়ে গেলে মেমোরি স্বয়ংক্রিয়ভাবে খালি করে (Memory Leak রোধ করে)।

#### কেন Clean Architecture (Domain, Data, Presentation, Core)?
- **Dependency Rule:** আপনার কোর বিজনেস লজিক (Domain) কোনো ফ্রেমওয়ার্কের ওপর নির্ভর করবে না।
  - **Domain Layer:** শুধু পিওর ডার্ট কোড (Entity & Use Cases)। কালকে যদি Flutter বদলে অন্য কিছুতে যান, এই লজিক অক্ষত থাকবে।
  - **Data Layer:** API কল (Dio) এবং লোকাল স্টোরেজের দায়িত্ব নেবে।
  - **Presentation Layer:** Riverpod কন্ট্রোলার এবং স্ক্রিন উইজেট।
  - **Core Layer:** নেটওয়ার্ক ক্লায়েন্ট, এরর টাইপস, থিম টোকেন ইত্যাদি।

### ৩.২ Backend: Node.js (TypeScript) + NestJS (Modular Monolith)

#### কেন সাধারণ Express.js নয়, NestJS?
- **আর্কিটেকচারাল ডিসিপ্লিন:** Express-এ একেক ডেভেলপার একেক নিয়মে কোড লেখে, যা বড় প্রজেক্টে জগাখিচুড়ি হয়ে যায়। 
- **Built-in Dependency Injection (DI):** সার্ভিসগুলোকে সহজে টেস্ট ও মক করার জন্য NestJS-এ ডিপেন্ডেন্সি ইনজেকশন বিল্ট-ইন থাকে।
- **স্বয়ংক্রিয় Swagger/OpenAPI ডকুমেন্টেশন:** কন্ট্রোলারে কোড লিখলেই ব্রাউজারে সুন্দর ইন্টারেক্টিভ API ডকুমেন্টেশন তৈরি হয়ে যায় (`/api/docs`)।
- **এন্টারপ্রাইজ স্ট্যান্ডার্ড:** ইউরোপ, আমেরিকা ও রিমোট জবের এন্টারপ্রাইজ ব্যাকএন্ডে NestJS অত্যন্ত জনপ্রিয়।

#### কেন TypeScript?
- জাভাস্ক্রিপ্ট ডায়নামিক টাইপড হওয়ায় রানটাইমে অজস্র বাগ হয় (`undefined is not a function`)। TypeScript স্ট্যাটিক টাইপিং নিশ্চিত করে, ফলে কোড লেখার সময়ই এরর ধরা পড়ে।

### ৩.৩ Database: PostgreSQL 16 + Prisma ORM

#### রুম বুকিং সিস্টেমে কেন NoSQL (MongoDB/Firestore) নয়, Relational Database (PostgreSQL)?
1. **রিলেশনাল ডাটা ইন্টিগ্রিটি:** ইউনিভার্সিটি -> ডিপার্টমেন্ট -> ব্যাচ -> রুম -> শিডিউল — এই ডাটাগুলো গভীরভাবে একে অপরের সাথে সম্পর্কিত। PostgreSQL-এর **Foreign Key (FK)** নিশ্চিত করে যে ভুল বা এতিম (orphan) ডাটা ডাটাবেজে থাকতে পারবে না।
2. **ACID ট্রানজ্যাকশন:** যদি দুই জন CR একই সেকেন্ডে একই রুম বুক করার চেষ্টা করে, PostgreSQL ট্রানজ্যাকশন লকিংয়ের মাধ্যমে নিশ্চিত করে যে একজনই পাবে, অন্যজন কনফ্লিক্ট এরর পাবে। Firestore বা NoSQL-এ এটা হ্যান্ডেল করা জটিল ও ব্যয়বহুল।
3. **Prisma ORM:** কাঁচা SQL কুয়েরি লেখার চেয়ে টাইপ-সেফ ORM ব্যবহার করলে ডাটাবেজের যেকোনো টেবিল সরাসরি TypeScript অবজেক্ট হিসেবে পাওয়া যায়। কোনো ফিল্ডের নাম ভুল লিখলে সাথে সাথে কোডে এরর দেখাবে।

### ৩.৪ Caching & Real-Time: Redis 7 + WebSockets

#### কেন Redis দরকার?
- **ডাটাবেজের লোড কমানো:** বারবার একই রুমের স্ট্যাটাস জানার জন্য PostgreSQL-এ কুয়েরি চালালে ডাটাবেজ স্লো হয়ে যাবে। রুমের লাইভ স্ট্যাটাস র‍্যামে (RAM - Redis) ক্যাশ করে রাখা হয়, যা মাইক্রোসেকেন্ডে রেসপন্স দেয়।
- **Rate Limiting:** যাতে কেউ স্ক্রিপ্ট দিয়ে ব্যাকএন্ডে স্প্যাম রিকোয়েস্ট পাঠাতে না পারে।
- **Pub/Sub (Publish/Subscribe):** একটি সার্ভার ইনস্ট্যান্স থেকে অন্য ইনস্ট্যান্সে রিয়েল-টাইম মেসেজ পাঠানো।

#### কেন WebSocket দরকার (Polling বনাম WebSockets)?
- **HTTP Polling (খারাপ পদ্ধতি):** মোবাইল অ্যাপ প্রতি ২ সেকেন্ড পর পর সার্ভারকে জিজ্ঞেস করে: "রুম কি খালি হয়েছে?" — এতে ক্লাউড বিল আকাশচুম্বী হয় এবং ব্যাটারি শেষ হয়।
- **WebSockets (সেরা পদ্ধতি):** একটি লাইভ কানেকশন ওপেন থাকে। যখনই CR কোনো রুমের স্ট্যাটাস আপডেট করবে, সার্ভার নিজে থেকে সাথে সাথে সব স্টুডেন্টের মোবাইলে ইভেন্ট পুশ করবে। কোনো রিফ্রেশ বাটন প্রেস করতে হবে না!

### ৩.৫ DevOps & Infrastructure: Docker & GitHub Actions (CI/CD)

#### কেন Docker এবং Docker Compose?
- **"It works on my machine" সমস্যার সমাধান:** আপনি Windows-এ কোড করছেন, সার্ভার চলে Linux-এ, অন্য কলিগ হয়তো Mac ব্যবহার করছে।
- Docker একটি লাইটওয়েট ভার্চুয়াল কন্টেইনার তৈরি করে যার ভেতর ঠিক একই ভার্সনের Node, Postgres, Redis রান করে। ফলে সব মেশিনে ১০০% একই রেজাল্ট পাওয়া যায়।
- `docker compose up -d` দিলে ১ সেকেন্ডে ব্যাকএন্ড, ডাটাবেজ ও ক্যাশ চালু হয়ে যায়।

#### কেন GitHub Actions (CI/CD)?
- Continuous Integration (CI): আপনি বা আপনার টিমমেট যখনই গিটহাবে কোড পুশ করবেন বা PR (Pull Request) পাঠাবেন, রোবট স্বয়ংক্রিয়ভাবে কোড স্ক্যান করবে:
  - কোনো লিন্ট এরর আছে কি না?
  - সব ইউনিট টেস্ট পাস করেছে কি না?
  - বিল্ড তৈরি হচ্ছে কি না?
- যদি একটি টেস্টও ফেইল করে, কোড মেইন ব্রাঞ্চে মার্জ হতে দেওয়া হবে না। এটি টপ কোম্পানিগুলোর বাধ্যতামূলক রুল।

## ৪. আগামী ৫ বছরের চাকরির বাজারে এটি আপনাকে কীভাবে এগিয়ে রাখবে?

টপ টেক কোম্পানিগুলোতে ফ্রেশার বা জুনিয়রদের মধ্যে সবাই সাধারণ টু-ডু অ্যাপ বা ইকমার্স ক্লোন বানিয়ে নিয়ে আসে। কিন্তু ইন্টারভিউয়াররা খোঁজেন:

1. **System Design জ্ঞান:** আপনি জানেন কেন নো-এসকিউএল এর বদলে পোস্টগ্রেস বেছে নেওয়া হয়েছে, কেন ক্যাশিং দরকার।
2. **Clean Architecture ও SOLID নীতি:** আপনি বোঝেন কিভাবে UI থেকে ডাটাবেজকে আলাদা রাখতে হয়।
3. **Automated Testing:** আপনি জানেন `mocktail` বা `jest` দিয়ে কীভাবে মক করে ইউনিট টেস্ট লিখতে হয়।
4. **DevOps সচেতনতা:** আপনি ডকার ফাইল এবং CI/CD কনফিগার করতে পারেন।
5. **Full-Stack সক্ষমতা:** আপনি শুধু অ্যাপ ফ্রন্টএন্ড বানাননি, ইন্ডাস্ট্রিয়াল ব্যাকএন্ড ও রিয়েল-টাইম ইঞ্জিন ডিজাইন করেছেন।

## ৫. প্রজেক্ট ফোল্ডার স্ট্রাকচার ওভারভিউ

```
UniRoom-Live/
├── backend/                 # NestJS এন্টারপ্রাইজ ব্যাকএন্ড
│   ├── src/
│   │   ├── common/          # গার্ডস, ইন্টারসেপ্টর, এরর ফিল্টার
│   │   ├── modules/
│   │   │   ├── auth/        # লগইন, সাইনআপ, JWT রিফ্রেশ টোকেন, RBAC
│   │   │   ├── rooms/       # রুম তৈরি, আপডেট, কনফ্লিক্ট চেকার
│   │   │   ├── schedules/   # রুটিন ও শিডিউল ম্যানেজমেন্ট
│   │   │   └── realtime/    # WebSocket গেটওয়ে এবং Redis ব্রডকাস্ট
│   │   └── database/        # Prisma স্কিমা ও মাইগ্রেশন
│   ├── Dockerfile           # ব্যাকএন্ড কন্টেইনারাইজেশন
│   └── test/                # ব্যাকএন্ড ইউনিট ও ইন্টিগ্রেশন টেস্ট
│
├── mobile/                  # Flutter ৩.x + Riverpod ২.x ক্লায়েন্ট
│   ├── lib/
│   │   ├── core/            # নেটওয়ার্ক ক্লায়েন্ট (Dio), থিম, এরর হ্যান্ডলিং
│   │   ├── features/        # Auth, Rooms, University (Clean Architecture)
│   │   │   ├── domain/      # এন্টিটি এবং ইউজ-কেস (Pure Dart)
│   │   │   ├── data/        # API ডাটা সোর্স এবং রিপোজিটরি
│   │   │   └── presentation/# Riverpod Notifiers এবং UI স্ক্রিন
│   │   └── main.dart        # এন্ট্রি পয়েন্ট
│   └── test/                # মোবাইল ইউনিট এবং উইজেট টেস্ট
│
├── docs/                    # আর্কিটেকচার সিদ্ধান্ত (ADRs) ও ডায়াগ্রাম
├── docker-compose.yml       # Postgres + Redis + API একসাথে রান করার কনফিগ
├── complete_project.md      # মূল সিস্টেম ডিজাইন ব্লুপ্রিন্ট
├── guide.md                 # এই বাংলা লার্নিং গাইড
└── README.md                # গিটহাব শোকেস পেজ
```

## ৬. ইন্টারভিউ বা ডিফেন্সে প্রজেক্টটি কীভাবে উপস্থাপন করবেন?

> **"আমি UniRoom-Live 2.0 প্রজেক্টটি তৈরি করেছি ক্লিন আর্কিটেকচার এবং ডোমেইন-ড্রাইভেন ডিজাইন অনুসরণ করে। এটি একটি মাল্টি-টেন্যান্ট রিয়েল-টাইম ক্লাসরুম অর্কেস্ট্রেশন সিস্টেম। এর ব্যাকএন্ডে রয়েছে NestJS, PostgreSQL এবং Redis, যা WebSockets এর মাধ্যমে সাব-সেকেন্ড ল্যাটেন্সিতে রুমের স্ট্যাটাস সিনক্রোনাইজ করে। মোবাইল অংশে ব্যবহৃত হয়েছে Flutter এবং Riverpod 2.x, যেখানে স্টেট ও বিজনেস লজিক সম্পূর্ণভাবে UI থেকে ডিকাপল্ড। পুরো সিস্টেমটি ডকারাইজড এবং GitHub Actions CI/CD পাইপলাইনের মাধ্যমে অটোমেটেড টেস্টিং নিশ্চিত করা হয়েছে।"**
